개요

영어권 데이터 중심으로 발전한 AI 서비스는 일상 언어로 쓰는 한국어 감정 일기의 뉘앙스를 담아내기 어렵습니다. 그렇다고 대형 LLM으로 감정 분류까지 맡기면 비용과 응답 속도 부담이 큽니다. 그래서 감정 분류는 경량 한국어 모델이, 추천 문장 생성은 LLM이 맡는 하이브리드 구조로 설계했습니다.

내가 맡은 일

3인 팀 프로젝트로 시작했으며, 모델링부터 배포까지 구현은 제가 맡아 완성했습니다.

  • 데이터와 모델 — 감정 데이터셋 비교·선정, 전처리, klue/roberta-base 파인튜닝과 평가
  • 백엔드 — Flask 앱 팩토리 구조, REST API, 인증, Supabase(PostgreSQL) 스키마 설계
  • 프론트엔드 — 일기 작성·분석 결과·감정 달력·마이페이지 UI
  • 배포 — Docker, GitHub Actions를 통한 Hugging Face Spaces 자동 배포

문제를 풀어간 과정

1. 일기에 맞는 학습 데이터 고르기

대표적인 한국어 감정 데이터셋 세 가지를 일기라는 도메인에 맞는지 기준으로 비교했습니다.

데이터셋특징판단
NSMC (영화 리뷰)긍정/부정 이진 분류감정 해상도가 낮아 제외
KOTE (온라인 댓글)43개 감정, 타인을 향한 평가·비속어 중심내면을 서술하는 일기와 도메인 불일치로 제외
AI Hub 감성대화 말뭉치상담 대화체, 60개 세부 감정일기 문체와 가장 가까워 채택

60개 세부 감정은 추천에 쓰기 좋게 6대 감정(기쁨·슬픔·분노·불안·상처·당황)으로 묶었습니다. NSMC를 병합해 학습한 비교 실험에서는 정확도가 46.4%로 가장 낮게 나와, 데이터를 많이 넣는 것보다 도메인에 맞는 데이터를 고르는 것이 중요하다는 걸 확인했습니다.

2. 클래스 불균형: 오버샘플링에서 클래스 가중치로

초기 모델(V1)의 혼동 행렬을 보니 데이터가 가장 적은 '기쁨'을 38.6%나 잘못 분류하고 있었습니다.

  1. 오버샘플링 — 소수 클래스를 복제했더니 같은 데이터를 반복 학습해 과적합이 생기고, GPU 메모리 부족(OOM)이 잦아짐.
  2. 클래스 가중치 — 데이터를 늘리는 대신 소수 클래스를 틀렸을 때 손실을 더 크게 부여. 혼동 행렬을 근거로 '기쁨' 6.0, '당황' 4.5의 가중치를 설정.
  3. 결과 — '기쁨' 오분류율이 38.6%에서 1.9%로 감소하고, 예측이 정답 대각선 방향으로 고르게 모임.

3. 대용량 모델 배포 오류

학습 체크포인트(optimizer.pt 등)를 포함한 모델 파일이 800MB를 넘어 Hugging Face Spaces의 1GB 저장 한도를 초과하면서 배포가 실패했습니다. 모델을 앱 코드와 분리해 Hugging Face Hub에 올리고, 앱이 시작될 때 내려받도록 구조를 바꿔 해결했습니다. 모델은 앱 시작 시 한 번만 로드해 요청마다 다시 불러오지 않게 했고, 이 구조 덕분에 코드만 push해도 빠르게 배포됩니다.

4. 틀릴 수 있는 AI를 쓰는 UX

분석 신뢰도가 낮을 때는 사용자가 직접 감정을 고를 수 있도록 감정 칩 UI를 동적으로 보여주고, 사용자가 확정한 감정으로 추천을 생성합니다. 모델이 틀려도 서비스 경험이 이어지도록 한 장치입니다.

시스템 구성

Frontend

HTML · CSS · JavaScript. 책 모양 인터페이스(CSS 3D 페이지 넘김), Fetch API 비동기 렌더링, 감정 달력 대시보드

Backend

Python · Flask(앱 팩토리, 블루프린트), REST API(/api/predict 등), 해시 기반 인증

AI

klue/roberta-base 파인튜닝(PyTorch, Transformers), Gemini API 추천 생성

Data / DevOps

Supabase(PostgreSQL), Docker, GitHub Actions, Hugging Face Spaces·Hub

학습은 RTX 4060 Laptop GPU에서 batch 16, learning rate 1e-5로 10 에포크(약 2시간) 진행했습니다.

결과와 한계

  • 결과 — 라이브 데모를 공개했고, 개발 과정을 졸업작품 논문으로 정리했습니다.
  • 한계 1 — 의미가 비슷한 '슬픔'과 '상처'를 서로 혼동합니다. 일기에서는 두 감정이 함께 서술되는 경우가 많기 때문입니다.
  • 한계 2 — 최신 GPT 계열 기반 선행 연구(F1 0.91 이상)와 비교하면 분류 성능에 격차가 있습니다. 대신 경량 모델이라 운영 비용과 응답 속도 면에서 유리한 구조입니다.
  • 다음 단계 — 역번역으로 경계가 모호한 클래스의 데이터를 늘리고, 긍정·부정을 먼저 나누는 계층적 분류를 적용해 보려 합니다.
