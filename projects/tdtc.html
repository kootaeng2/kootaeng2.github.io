KT 에이블스쿨 9기 AI트랙 · 팀 프로젝트

TDTC · 시켜줘 네 장터매니저
전통시장 인파 분석·안전탐지 관제 AI

CCTV 영상으로 전통시장의 인파 밀집도와 위험도(CRI)를 실시간 분석하고, 위험이 이어지면 관제 화면 경보와 자동 신고까지 연결하는 B2G 솔루션입니다.

에이블스쿨 우수상 7인 팀 2026.07 ~ 2026.08 (8주) B2G · 한국관광공사

개요

전통시장은 통로가 좁고 구조가 복잡해 사람이 몰리면 위험이 빠르게 커지지만, 현장은 CCTV를 사람이 눈으로 지켜보는 데 그쳐 사고가 난 뒤에야 대응이 시작됩니다. 한국관광공사의 「2026 AI 기반 지역관광 문제해결」 공고와 정부의 AI 기반 인파관리 확산 방향에서 출발해, 관제 요원이 놓치기 쉬운 밀집 위험을 영상에서 먼저 읽는 시스템을 목표로 했습니다.

디지털 트윈 정책 시뮬레이션

  • 정책 공문에서 조건을 자동 추출해 시나리오 설정
  • 에이전트 기반 모델(Mesa)로 정책 적용 전·후 비교
  • 3D 시각화와 RAG 기반 보고서 초안 생성

CCTV 영상 관제 대시보드 · 제가 속한 파트

  • CCTV 영상에서 구역별 인원·밀집도 산출
  • 위험도(CRI) 계산과 실시간 시각화
  • 위험 상태가 지속되면 경보와 자동 신고

내가 맡은 일

CCTV 영상 관제 대시보드 파트를 3명이 나눠 맡았고, 저는 AI 추론 서버와 위험도 계산, LiDAR 검토를 담당했습니다.

  • CSRNet 학습·평가 — 고밀도 군중에 맞는 밀도 추정 모델을 학습하고 현장 영상으로 검증
  • 군중 위험도 알고리즘 — 구역별 밀집도를 행정안전부 기준(위험 6명/㎡ 이상)에 맞춰 위험도로 환산
  • FastAPI 기반 관제 서버 — 영상 추론과 지표를 대시보드·백엔드로 전달
  • AWS S3 영상·DB 적재 — 분석 결과와 영상을 백엔드와 연동해 저장
  • LiDAR 3D 탐지 학습과 퓨전 검토 — 도입, 결합 실험, 제거 결정까지 (아래 참고)

YOLO11n 기반 2D 탐지·모자이크 파트는 팀원이 담당했고, 그 결과를 서버에서 함께 연결했습니다.

문제를 풀어간 과정

1. 탐지 모델에서 밀도 추정 모델로 전환

처음에는 경량 탐지 모델 YOLO11n으로 인원을 세려 했지만, 데이터가 박스가 아니라 사람 머리 점 좌표로 라벨링되어 있었고 군중이 겹치는 구간에서 탐지율이 급감했습니다.

  1. YOLO11n 초기 평가 — mAP@50 0.605. 학습량 부족과 야간 화질 저하로 낮게 나옴.
  2. 가상 박스 보강 — 헤드 포인트를 중심으로 80px 가상 박스를 생성해 mAP@50 0.808까지 개선했지만, 학습에 쓰지 않은 현장 영상에서는 흔들림과 오탐이 남음.
  3. CSRNet으로 전환 — 박스 대신 픽셀 단위 밀도맵을 만들고 적분해 인원을 계산. 학습 데이터 6만 장 이상, KDTree 기반 적응형 가우시안 커널로 정답 밀도맵을 생성.
  4. 불안정성 진단 — 초기 모델(MAE 4.4)은 환경이 다른 영상에서 실제보다 8~10명 적게, 비슷한 환경에서는 130명으로 크게 과대 예측. 특정 환경 데이터에 과적합된 것이 원인.
  5. 튜닝 — 증강(Random Crop, Color Jitter, Flip)과 후반부 과적합 확인 후 가장 일반화가 좋은 Epoch 8 가중치 선정. 후처리 임계값 오류로 생기던 히트맵 노이즈도 수정.

실제 인원과 시각적 일치

YOLO11n은 버리지 않고 빠른 처리 속도를 살려 실시간 얼굴 모자이크로 역할을 바꿨습니다. 모델마다 잘하는 일을 나눠 맡긴 셈입니다.

2. LiDAR 도입, 검증, 제거

영상 기반 밀도(픽셀 공간)를 실제 단위의 공간 점유율로 보완·검증할 수 있는지 보려고 LiDAR를 검토했습니다. PointPillars 백본과 CenterPoint 헤드로 3D 탐지 파이프라인을 만들고, CSRNet 결과와 합친 종합 스코어링을 실험했습니다.

결과 — LiDAR를 더하자 오히려 CSRNet의 성능이 떨어졌습니다. 결합을 고집하지 않고 LiDAR를 제거하고 CCTV 중심으로 범위를 좁히기로 결정했습니다. 기능을 더하는 것보다, 실제로 개선되는지 측정하고 안 되면 빼는 판단이 더 중요하다는 걸 배운 경험입니다.

기획·설계 산출물

8주 동안 주차별로 산출물을 쌓아가며 진행했습니다. 아래는 핵심 문서의 요약입니다.

과제 정의서, 요구사항 정의서, 아키텍처 정의서, 서비스 플로우, ERD, UI/UX 설계서

품질 평가·완료 (6~8주)

최종 발표 PPT, 1페이지 솔루션 설명서, 시연 영상, 소스 코드

결과와 한계

  • 결과 — KT 에이블스쿨 9기 우수상. CCTV 영상에서 위험도 산출, 관제 대시보드, 경보·자동 신고까지 한 흐름으로 연결.
  • 한계 1 — 지자체 CCTV 자료를 받지 못해 망원시장에서 직접 촬영한 영상 등으로 검증했습니다. 실제 설치 환경과는 차이가 있을 수 있습니다.
